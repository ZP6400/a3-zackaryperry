This project contains a small game titled Black Hole Boogie, in which the user needs to press one of four keys as fast as they can before a ball gets sucked up by the black holes surrounding it. The ball will slide in the direction of the black hole with the key that needs to be pressedl upon achieving this, it will be attracted towards a different hole instead. The ball speeds up as the game progresses, and eventually ends after 1-2 minutes of gameplay. Following this, the player is suggested to submit a username alongside their score, which consists of the amount of time they survived and the score they acquired. This fields are used to derive the amount of points per second (pps) the player racked up, as well as the respective ranking that this gets them (from C Rank to S Rank).

A combination of both CSS Grid and Flexbox was used in the styling/positioning of this project. CSS Grid was used to establish the side-by-side card arrangement for when the site is accessed on desktop, with the leaderboard spanning below across both columns (a fallback was also implemented for mobile screens, where a single-column stack is implemented instead). Flexbox was then used to manage more minor details, such as aligning HUD text, centering the key indicators within the black holes, stacking the form inputs properly, etc. Finally, absolute positioning was also used to place the ball and black holes in an organized way within the game space.

## Technical Achievements
- **Created a single-page app**: The Black Hole Boogie game operates fully on a single page, without needing any reloads in order to display updated scores on the leaderboard. This was accomplished using asynchronous fetch() calls with JSON payloads. Whenever the form for score recording was submitted, the default option of reloading the page would be prevented. Instead, the frontend packages the input values into a JSON object and sends it directly to the server in the background. The server processes the submission, calculates the derived fields, and sends back the entire updated list of scores. As soon as the client receives that response, the table rows are rebuilt on the spot so the player immediately sees their new score without any interruption to the page.

- **Added the ability to modify existing data**: In addition to being able to insert and delete the data for a submitted score, editing was implemented as well. Each table row on the frontend features an edit action button. When clicked, it grabs that row's information, populates the input fields with the existing values, tracks the row's ID in a hidden input, and changes the submit button to "Update Score." When submitted, the frontend sends a POST request to /edit instead of /submit. The server finds the matching entry by its ID, runs the updated numbers back through the derived field logic to recalculate the pps and ranking, and replaces the old record in memory before sending the refreshed leaderboard back to the client."
